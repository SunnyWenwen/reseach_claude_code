# PR 審查清單

> 此檔案由 SKILL.md 在需要時載入，不會預設佔用 context。

## 程式碼品質
- [ ] 函式/變數命名清晰，符合語言慣例
- [ ] 沒有重複程式碼（DRY 原則）
- [ ] 函式單一職責，長度合理（建議 < 50 行）
- [ ] 沒有硬編碼的魔法數字或字串
- [ ] 移除了所有 debug 用的 console.log / print

## 安全性
- [ ] 沒有 SQL Injection 風險（使用參數化查詢）
- [ ] 沒有 XSS 風險（輸出有正確 escape）
- [ ] 沒有敏感資訊（密碼、token）寫死在程式碼中
- [ ] 輸入驗證在邊界層（API / UI）有確實執行
- [ ] 權限檢查邏輯正確

## 測試
- [ ] 新增的功能有對應的單元測試
- [ ] 邊界條件（null、空值、極值）有測試覆蓋
- [ ] 現有測試沒有因為此 PR 而損壞

## 架構與設計
- [ ] 變更符合現有的架構模式
- [ ] 沒有引入不必要的依賴
- [ ] 公開 API 的設計合理，向下相容（或有明確的 breaking change 說明）

## 文件
- [ ] 公開函式/方法有適當的註解或文件
- [ ] README 或 CHANGELOG 有對應更新（若適用）
